# Universal TV Remote

A native Android/iOS remote for compatible Android TV and Google TV devices on the same Wi-Fi network. Local communication only: no accounts, backend, advertising, or analytics.

The Kotlin and Swift adapters implement Bonjour/NSD discovery, RSA client identities, hexadecimal pairing, pinned TLS, Protobuf framing, startup negotiation, ping responses, and key injection. The app includes onboarding, discovery/manual address entry, pairing, a D-pad/touchpad remote, saved devices, and settings.

**Status: development implementation, not a hardware-validated release.** No physical TV or phone was available. Simulator and fixture results do not establish TV compatibility. Keyboard input is unavailable until IME behavior is validated. Standby/wake and individual controls remain subject to TV firmware and application behavior. See [TESTING.md](TESTING.md) for actual results and outstanding gates.

## Run locally

Use Node 24.19+, Java 17, Android SDK platform 37, and Xcode 26.4 with CocoaPods. iOS minimum is 16.4; Android minimum is 7 (API 24). Expo Go cannot load this application's native module.

```sh
npm ci
npx expo prebuild
npm run ios
# Or, with an Android emulator/device:
npm run android
```

Subsequent JavaScript development uses `npm start`. Native code or configuration changes require rebuilding the development client. SDK 58 prebuild recreates native directories by default; use `--no-clean` for an incremental configuration sync. Generated root `ios/` and `android/` projects are ignored; edit Expo configuration and the local module instead. Development identifiers are `dev.universaltv.remote` and are configurable before release.

If Watchman stalls on generated native files, start Metro with `TVREMOTE_DISABLE_WATCHMAN=1 npm start`. For an Android emulator, `adb reverse tcp:8081 tcp:8081` lets the development client use `http://localhost:8081`. The E2E flows also handle entering this address in the development launcher.

Allow local-network access when discovery requests it. The phone must use Wi-Fi; internet connectivity is unnecessary. If discovery finds nothing, enter one private IPv4 address. The app does not scan subnets. Forget removes local credentials and metadata; it does not revoke access on the TV.

## Validation

```sh
npm run typecheck
npm run lint
npm run format:check
npm run test:coverage
node scripts/verify-fixtures.mjs
node scripts/verify-native-linking.mjs
npx expo install --check
npx expo-doctor
swift test --package-path modules/tv-remote-native/ios/Core
node scripts/test-ios-credentials.mjs
# After prebuild:
cd android
./gradlew :tv-remote-native:testDebugUnitTest :app:assembleDebug
```

Native protocol generation requires protoc 36.2 and protoc-gen-swift 1.39.0 on PATH; run `npm run native:generate`. Generated Swift types are checked in; Android types are generated by Gradle. Preserve `package-lock.json` and the Swift package's `Package.resolved`.

## Explicit UI test build

```sh
APP_VARIANT=ui-test npx expo prebuild
APP_VARIANT=ui-test npm run ios
```

This build uses the separate identifier `dev.universaltv.remote.uitest`, displays a persistent **UI TEST · SIMULATED TV** banner, and uses pairing code `A1B2C3`. It never contacts a TV. Production builds instantiate the real adapter; a missing native module produces an actionable error. The fixture adapter requires both the explicit configuration flag and the exact test application identifier.

Keep `APP_VARIANT=ui-test` set when starting Metro for this variant. See [e2e/README.md](e2e/README.md) for reproducible emulator commands and limitations. Fixture credential references are in memory; a simulated reconnect in one run does not establish credential persistence across app restarts.

Default Android target API is 36 with compile API 37. `ANDROID_TARGET_SDK=37` also declares and requests the applicable local-network permission. This opt-in permission path still needs an API 37 device test.
